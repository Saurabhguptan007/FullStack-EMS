# FullStack EMS

FullStack EMS is a modern employee management system built with React and Vite. It gives organizations a clean and practical way to manage their workforce, from employee records and attendance tracking to leave approvals and payroll processing.

The app is designed around two main roles: admin and employee. The admin portal helps HR or management teams oversee the organization, manage employee profiles, monitor attendance, approve leave requests, generate payslips, and handle the day-to-day operations of the team. The employee portal gives staff a simple way to view their dashboard, check attendance, request leave, access payslips, and update personal settings.

## Overview

This project acts like a lightweight HR dashboard for a company that wants a streamlined digital workplace. Instead of juggling spreadsheets and disconnected tools, teams can use one interface to keep things organized and easier to follow.

Some of the key features in the app include:

- Dashboard overview with quick stats and summaries
- Employee management for adding, editing, and viewing team members
- Attendance tracking and visibility into daily attendance activity
- Leave management with request and approval flows
- Payslip generation and printable salary slips
- Responsive layout for desktop and mobile use
- Role-based navigation and portal experience

The full interface is built for a smooth user experience and uses a modern design with a strong emphasis on clarity and speed.

## Tech Stack

- React
- Vite
- React Router
- Tailwind CSS
- Lucide React icons

## How to run the app

From the project folder, follow these steps:

1. Open your terminal in the `client` directory.
2. Install the project dependencies:

   ```bash
   npm install
   ```

3. Start the development server:

   ```bash
   npm run dev
   ```

4. Open the local URL shown in the terminal, usually:

   ```bash
   http://localhost:5173
   ```

You can also build the app for production with:

```bash
npm run build
```

## Notes

This project currently uses demo/mock data for the interface, so it is best suited for frontend demo and UI exploration. If you want, the next step would be connecting it to a backend API and a real database for live employee management.
